# 发布与协作

## 日常同步

在仓库目录修改后，先运行 README 中的检查，再 `git add` 需要提交的源码、`git commit` 和 `git push`。`main` 的推送自动构建 GitHub Pages。分享页面链接即可让别人体验模拟流程；连接真实板需要本地分发包与依赖。

发布目录是 `web/`，所有资源用相对链接，因此适用于 GitHub Pages 的 `/仓库名/` 子路径。页面不通过跨域请求操作 localhost，也不依赖浏览器 Web Serial 支持。真实采集界面由用户自己的回环服务提供。

## 下载包

`python3 scripts/package.py` 生成 ZIP 和 SHA256；Pages 工作流会将同一分发包放入网站 `downloads/`，让访客直接下载。ZIP 采用明确的源码文件白名单，而不是整个项目目录压缩。

分发包包含启动脚本和源码，依赖 Python 3.10+ 与用户自行安装的 OpenBCI GUI Java / BrainFlow。macOS 为当前真实硬件验证平台；其他平台需对实际 GUI 导出目录、原生库架构、串口权限和板卡行为做实机验证。

## 研究数据

`recordings/`、`research/`、运行时和测试记录被 `.gitignore` 排除，也不在打包白名单里。`.gitignore` 不会删除以前已提交的数据；如果在已有仓库中采用此项目，先检查 `git ls-files`，避免把已有受试者数据留在历史中。

## 建议的协作方式

为界面、采集驱动和分析算法分开提交。协议或算法修改需记录依赖版本、板卡配置、数据格式和测试范围；界面改动先验证开始 / 停止、状态同步、重复 marker、切换视图时取消刺激与下载。

用户佩戴电极后的数据属于自己的研究数据；分享软件并不意味着分享记录。实际实验的知情同意、伦理审批和数据管理由研究者按所在机构要求开展。
